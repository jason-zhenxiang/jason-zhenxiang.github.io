#### HDL与VHDL基础
- **硬件描述语言 Hardware description languages**
  - 是用来**描述硬件**的语言
  - 两种常见语言：
    - **VHDL**：**V**ery High Speed Integrated Circuits **H**ardware **D**escription **L**anguage
      - 1983年由DOD开发；IEEE Standard 1076-1987/1993/200x；基于ADA语言开发
    - **Verilog**
      - IEEE Standard 1364-1995/2001/2005；基于C语言开发
- **硬件描述语言的应用**
  - 对数字系统进行**建模与文档化**
    - 支持不同抽象层次的描述，如行为级、结构级
  - 验证设计正确性
  - 实现电路综合，将高层次抽象描述转为低层次硬件实现
- **VHDL的介绍**
  - VHDL具有如下用途：**将电路文档化、模拟电路、整合设计描述**
  - **整合**指的是将设计描述简化为更低层次的表示形式
  > 这里的“更低层次”，可以类比汇编语言之于高级语言会更接近计算机的底层，VHDL相比于电路图也会更接近硬件设计的底层，这样带来的好处是响应速度更快，但是可读性降低，有阅读门槛
- **为什么使用VHDL？**
  - 能够快速上市，支持大规模电路、高级语法构造
  - 同一套代码可同时用于设计和仿真，无需重复编写
  - 支持器件无关设计，可跨厂商移植
#### 硬件描述思想与设计抽象层次
- **VHDL与传统编程语言的区别**
  - 传统编程语言（过程式编程语言）提供怎么做的方法或执行步骤
    - 用于实现计算逻辑、完成数据处理、在特定硬件模型上按顺序执行
  - VHDL用于**描述系统本身**
    - 可以从多个视角对系统进行描述（行为视角、结构视角、功能特性视角等）
    - 描述可以处于不同的抽象层级：开关级、寄存器传输级、指令集体系
    - 描述可以用于：仿真（Simulation）或综合（Synthesis）
- **为什么需要描述系统？**
  - 保持设计规范；在投产之前先仿真验证；自动生成硬件设计

  - 需要一种统一的描述方式，来实现不同层级之间的转换

- **Gajski-Kuhn Y图**
> 同一个数字系统，可以从功能、结构、物理多个角度进行描述
  - HDL具有极强能力的原因：能在多个维度描述设计
    - 行为（系统做什么）、结构（系统由什么组成）、物理（系统真实长什么样）
    - 每个维度又有不同抽象层次的功能

#### VHDL基本设计单元
- VHDL设计描述包括两部分：**实体声明（ENTITY declaration）**和**架构体（ARCHITECTURE body）**
  - 实体声明描述设计的输入/输出
  - 架构体描述设计的内容或功能
  - 每一个架构体都需要一个实体声明，单独存在一个没有意义，通常将它们一起称为**ENTITY/ARCHITECTURE PAIR**
  > ENTITY对模块的结构进行定义，它只关注模块如何与外界进行通信，不在意模块内部的实现方式；而ARCHITECTURE与之相反，用来进行模块的内部实现，关注模块内部如何工作

  ```vhdl
  ENTITY and2 IS
  PORT (
      a, b : IN std_logic;
      f    : OUT std_logic
  );
  END and2;
  
  ARCHITECTURE behavioral OF and2 IS
  BEGIN
      f <= a AND b;
  END behavioral;
  ```
  - 例中，这个2输入与门的ENTITY部分就定义了模块名字`and`，输入端口`a, b`，输出端口`f`，类型`std_logic`；而ARCHITECTURE部分定义了模块的行`f = a AND b`
- **ENTITY 实体**
  - 模块可以看作一个黑箱，实体接口不知道内部的功能、内部实现方式
  - 实体通用格式：

  ```vhdl
  ENTITY entity_name IS
    -- optional generics

  PORT (
      name : mode type;
      ...
  );
  END entity_name;
  ```
    - `entity_name`是任意名字
    - `generics`用于定义参数化组件
    - `name`是端口名，可以存在多个
    - `mode`描述数据流方向
    - `type`表示该信号允许的取值类型
  - 实体的端口（Port）是和外部的通信点，通常对应芯片引脚，`name, mode, type`是端口的三要素
- **端口方向 Port mode**
  - 端口的MODE（模式）表示数据传输的方向
  - 四种模式：
    - `IN：`数据只能输入进实体
    - `OUT：`数据只能从实体输出，并且不能再模块内部再次读取使用
    - `INOUT：`数据双向传输。既可以输入，也可以输出
    - `BUFFER：`数据从模块输出，同时模块内部还能反馈使用这个信号
- **VHDL类型系统**
  - VHDL是强类型语言，不能把一种类型的信号直接赋给另一种类型
  - bit：只能取'0'或者'1'
  - bit_vector：由bit组成的向量
    - 例如：`SIGNAL a : BIT_VECTOR(0 TO 3);`，这里的`TO`指**升序索引**，如果是`DOWNTO`就是**降序索引**（工程习惯几乎都是降序）
  - `INTEGER: `用于loop索引，constants，generics和高层建模
  - `BOOLEAN：`布尔类型，值只能取`TRUE`或者`FALSE`
  - `ENUMERATED：`枚举类型，由用户自定义
  - **IEEE 1164**：为了解决BIT类型局限性而创建的标准包，支持9中逻辑值，可以用于多值逻辑系统
    - '0' -- 强制0
    - '1' -- 强制1
    - 'Z' -- 高阻态
    - 'L' -- 弱0
    - 'H' -- 弱1
    - '-' -- don't care
    - 'U' -- 未初始化（后三个仅在仿真中使用）
    - 'X' -- 未知
    - 'W' -- 弱未知
#### **Exercise #1: The Entity**
![vhdl练习1.png](/resources/数字逻辑电路/vhdl练习1.png)
```vhdl
LIBRARY ieee;
USE ieee.std_logic_1164.ALL;

ENTITY my_design IS
PORT (
    d       : IN     std_logic_vector(11 DOWNTO 0);
    oe, clk : IN     std_logic;
    ad      : INOUT  std_logic_vector(11 DOWNTO 0);
    a       : OUT    std_logic_vector(11 DOWNTO 0);
    int     : OUT    std_logic;
    as      : BUFFER std_logic
);
END my_design;
```
- VHDL大小写不敏感，clock, Clock, CLOCK都是一个东西
