#### HDL与VHDL基础
- **硬件描述语言 Hardware description languages**
  - 是用来**描述硬件**的语言
  - 两种常见语言：
    - **VHDL**：**V**ery High Speed Integrated Circuits **H**ardware **D**escription **L**anguage
      - 1983年由DOD开发；IEEE Standard 1076-1987/1993/200x；基于ADA语言开发
    - **Verilog**
      - IEEE Standard 1364-1995/2001/2005；基于C语言开发
- **硬件描述语言的应用**
  - 对数字系统进行**建模与文档化**
    - 支持不同抽象层次的描述，如行为级、结构级
  - 验证设计正确性
  - 实现电路综合，将高层次抽象描述转为低层次硬件实现
- **VHDL的介绍**
  - VHDL具有如下用途：**将电路文档化、模拟电路、整合设计描述**
  - **整合**指的是将设计描述简化为更低层次的表示形式
  > 这里的“更低层次”，可以类比汇编语言之于高级语言会更接近计算机的底层，VHDL相比于电路图也会更接近硬件设计的底层，这样带来的好处是响应速度更快，但是可读性降低，有阅读门槛
- **为什么使用VHDL？**
  - 能够快速上市，支持大规模电路、高级语法构造
  - 同一套代码可同时用于设计和仿真，无需重复编写
  - 支持器件无关设计，可跨厂商移植
#### 硬件描述思想与设计抽象层次
- **VHDL与传统编程语言的区别**
  - 传统编程语言（过程式编程语言）提供怎么做的方法或执行步骤
    - 用于实现计算逻辑、完成数据处理、在特定硬件模型上按顺序执行
  - VHDL用于**描述系统本身**
    - 可以从多个视角对系统进行描述（行为视角、结构视角、功能特性视角等）
    - 描述可以处于不同的抽象层级：开关级、寄存器传输级、指令集体系
    - 描述可以用于：仿真（Simulation）或综合（Synthesis）
- **为什么需要描述系统？**
  - 保持设计规范；在投产之前先仿真验证；自动生成硬件设计

  - 需要一种统一的描述方式，来实现不同层级之间的转换

#### VHDL基本设计单元
- VHDL设计描述包括两部分：**实体声明（ENTITY declaration）**和**架构体（ARCHITECTURE body）**
  - 实体声明描述设计的输入/输出
  - 架构体描述设计的内容或功能
  - 每一个架构体都需要一个实体声明，单独存在一个没有意义，通常将它们一起称为**ENTITY/ARCHITECTURE PAIR**
  > ENTITY对模块的结构进行定义，它只关注模块如何与外界进行通信，不在意模块内部的实现方式；而ARCHITECTURE与之相反，用来进行模块的内部实现，关注模块内部如何工作

  ```vhdl
  ENTITY and2 IS
  PORT (
      a, b : IN std_logic;
      f    : OUT std_logic
  );
  END and2;
  
  ARCHITECTURE behavioral OF and2 IS
  BEGIN
      f <= a AND b;
  END behavioral;
  ```
  - 例中，这个2输入与门的ENTITY部分就定义了模块名字`and`，输入端口`a, b`，输出端口`f`，类型`std_logic`；而ARCHITECTURE部分定义了模块的行`f = a AND b`
- **ENTITY 实体**
  - 模块可以看作一个黑箱，实体接口不知道内部的功能、内部实现方式
  - 实体通用格式：

  ```vhdl
  ENTITY entity_name IS
    -- optional generics

  PORT (
      name : mode type;
      ...
  );
  END entity_name;
  ```
    - `entity_name`是任意名字
    - `generics`用于定义参数化组件
    - `name`是端口名，可以存在多个
    - `mode`描述数据流方向
    - `type`表示该信号允许的取值类型
  - 实体的端口（Port）是和外部的通信点，通常对应芯片引脚，`name, mode, type`是端口的三要素
- **端口方向 Port mode**
  - 端口的MODE（模式）表示数据传输的方向
  - 四种模式：
    - `IN：`数据只能输入进实体
    - `OUT：`数据只能从实体输出，并且不能再模块内部再次读取使用
    - `INOUT：`数据双向传输。既可以输入，也可以输出
    - `BUFFER：`数据从模块输出，同时模块内部还能反馈使用这个信号
- **VHDL类型系统**
  - VHDL是强类型语言，不能把一种类型的信号直接赋给另一种类型
  - bit：只能取'0'或者'1'
  - bit_vector：由bit组成的向量
    - 例如：`SIGNAL a : BIT_VECTOR(0 TO 3);`，这里的`TO`指**升序索引**，如果是`DOWNTO`就是**降序索引**（工程习惯几乎都是降序）
  - `INTEGER: `用于loop索引，constants，generics和高层建模
  - `BOOLEAN：`布尔类型，值只能取`TRUE`或者`FALSE`
  - `ENUMERATED：`枚举类型，由用户自定义
  - **IEEE 1164**：为了解决BIT类型局限性而创建的标准包，支持9中逻辑值，可以用于多值逻辑系统
    - '0' -- 强制0
    - '1' -- 强制1
    - 'Z' -- 高阻态
    - 'L' -- 弱0
    - 'H' -- 弱1
    - '-' -- don't care
    - 'U' -- 未初始化（后三个仅在仿真中使用）
    - 'X' -- 未知
    - 'W' -- 弱未知

#### **Architecture与描述风格**
- Achitecture描述黑盒里面有什么，即描述实体的**结构**或者**行为**，描述可以是以下几种组合：
  - **结构描述（Structural descriptions）**：实例化基本模块，并连接它们
  - **行为/数据流表述（Behavioral/Dataflow descriptions）**：算法描述或布尔方程
- 结构通用格式：
  ```vhdl
  ARCHITECTURE arch_name OF entity_name IS

    -- optional signal declarations
  BEGIN

    -- VHDL statements
  END arch_name;
  ```
    - `arch_name：`任意名字
    - `entity_name：`结构必须绑定于某一个实体
    - `statements：`描述模块内部功能
- **几种VHDL描述风格**
  - **1.行为描述**：描述硬件做了什么，不描述硬件如何组成；接近自然语言，可读性高

  ```vhdl
  ENTITY compare IS PORT (
      a, b: IN std_logic_vector(0 TO 3);
      equals: OUT std_logic
  );
  END compare;

  ARCHITECTURE behavior OF compare IS
  BEGIN
      comp: PROCESS (a,b) --IF语句必须在PROCESS里面
      BEGIN
          IF a = b THEN
              equals <= '1';
          ELSE
              equals <= '0';
          END IF;
      END PROCESS comp;
  END behavior;
  ```

  - **2.数据流风格**：用并发赋值表达逻辑关系
  - **3.结构描述风格**：实例化组件并连接端口
  - **4.混合风格**：融合数据流、结构描述风格，行为描述与组件例化可共存
  - **比较：**在简单的设计中，几种不同风格的结果最终等价；在更复杂的设计中，某些描述方式可能生成更高效的电路；使用让设计更容易描述和维护的风格（选择合适的）
#### **运算符、模块生成与简单计数器**
在Warp4.0中，有一个叫`std_arith`的包，它可以重载（Overloading）算术运算和关系运算，让这些运算支持`std_logic, std_logic_vector, integer`。
- 使用这个包后，综合其会自动把这些运算符替换成加法器、计数器和比较器，并根据目标硬件进行优化，这就叫**模块生成（Module Generation）**
```vhdl
LIBRARY ieee;
USE ieee.std_logic_1164.ALL;
USE WORK.std_arith.ALL; -- 为了让'count <= count + 1;'合法

ENTITY count8 IS
PORT (
    clk   : IN std_logic;
    count : BUFFER std_logic_vector(7 DOWNTO 0)
);
END count8;

ARCHITECTURE arch_count8 OF count8 IS
BEGIN

    upcount: PROCESS (clk)
    BEGIN
        IF (clk'EVENT and clk = '1') THEN
            count <= count + 1;
        END IF;
    END PROCESS upcount;

END arch_count8;
```
#### **VHDL语句体系**
- **并发语句 Concurrent Statements**
  - Architecture中的VHDL语句都是并发执行的，不是执行完前一句，再执行这一句，而是所有语句同时存在、同时工作。得益于这个特性，并发语句的顺序不重要
  - 例子：布尔方程、WHEN-ELSE条件赋值、WITH-SELECT-WHEN选择赋值
- **顺序语句 Sequential Statements**
  - 有时我们需要对**复杂功能**（多层条件判断、状态机等）进行建模，在这种情况下，我们可以使用一种**算法**或者**模型**来描述这个功能。这就是通过**顺序语句**来实现的
  - 对于顺序语句来说，语句的**执行顺序（ORDER）**非常重要，因此我们使用*process*来标记一段顺序语句代码块的开始和结束
  - 每一个完整的*process*，都被视为**一个大的并发语句**（在一个architecture中可以有很多个process）
- **Process是什么？**
  - process要么是醒着的，要么是睡着的，也就是process只有**活跃**和**非活跃**两个状态
  - 一个process通常会有一个**敏感信号列表**（sensitivity list）
    - 当这个敏感列表中的某个信号发生变化时，这个process会被唤醒，然后其中所有的顺序语句都会被执行
    - 例：如果一个process的敏感列表里有时钟信号`clk`，那么每当时钟信号发生变化时，这个process就会变成活跃状态
  - 在process执行结束时，所有输出都会被赋值，然后process会重新进入“睡眠状态”，直到下一次敏感列表里的某个信号再次发生变化
  - **process通用模板：**
  ```vhdl
  label: PROCESS (sensitivity list)

  -- variable declarations

  BEGIN

  -- sequential statements

  END PROCESS label;
  ```
    - process的标签（label）和变量声明（variable declarations）都是可选的
    - 当敏感列表中的某个信号发生事件时，这个process就会被执行
#### **组合逻辑描述方法**
- 组合逻辑可以用**并发语句**来描述：
  - 布尔方程、when-else、with-select-when、组件实例化
- 组合逻辑也可以用**顺序语句**来描述：
  - if-then-else、case-when
- **使用布尔方程描述组合逻辑**
  - 布尔方程既可以用于**并发信号赋值语句**，也可以用于**顺序信号赋值语句**
![vhdl_四选一选择器.png](/resources/数字逻辑电路/vhdl_四选一选择器.png)
    - 输入：`a, b, c, d`；选择信号：`s`；输出：`x`
    - `s`是2位选择信号，选择器根据`s`的值从四个输入中选择一个送到`x`
- **选择性信号赋值：with-select-when**
  - 基于一个选择信号进行赋值；`WHEN`子句必须是**互斥的**；当没有指定所有条件时，使用`WHEN OTHERS`；只引用一次信号，只使用一个赋值操作符`<=`
  
  ```vhdl
  WITH selection_signal SELECT
  signal_name <= value_1 WHEN value_1 of selection_signal,
                value_2 WHEN value_2 of selection_signal,
                ...
                value_n WHEN value_n of selection_signal,
                value_x WHEN OTHERS;
  ```

  - **使用选择性信号赋值描述组合逻辑：**
![vhdl_四选一选择器_选择语句.png](/resources/数字逻辑电路/vhdl_四选一选择器_选择语句)
  - value值也可以是一个范围（例如`0 to 3`）
- **条件信号赋值：when-else**
  - 信号会根据条件被赋予一个值；任何简单表达式都可以作为条件；优先级按照出现顺序排列；只引用一次信号，只使用一个赋值操作符`<=`；使用最后的`ELSE`来避免锁存器

  ```vhdl
  signal_name <= value_1 WHEN condition1 ELSE
                value_2 WHEN condition2 ELSE
                ...
                value_n WHEN condition N ELSE
                value_x;
  ```

  - **使用条件信号赋值描述组合逻辑：**
![vhdl_四选一选择器_条件赋值.png](/resources/数字逻辑电路/vhdl_四选一选择器_条件赋值)
  - when条件不需要像with-select-when那样互斥，因为存在优先级顺序
- **使用顺序语句描述组合逻辑**
  - 组合逻辑不仅可以用并发赋值语句描述，也可以在process中用顺序语句描述；各个process，以及process和并发语句之间，是并发执行的
#### **Signal与Variable**
在process内部，signal赋值不是立即生效的，而是**延迟到process结束后统一更新**
  - 如何解决这个问题？
  - 当不能在process外部使用并发信号来解决这个问题时，可以使用一个**变量**来避免前面的问题
    - 变量与信号类似，但是只能在一个process内部使用，不能用于在不同process之间传递信息
    - 变量可以是任何合法的VHDL数据类型，赋给变量的值会立即可用
    - 变量赋值使用冒号`:`例如：`c := a AND b`
  - **变量赋值后立即生效，信号赋值延后生效**
#### **VHDL运算符与标识符**
- **原生运算符**
  - **逻辑运算符**：为`bit, bit_vector, boolen*`类型定义
    - `AND, NAND, OR, NOR, XOR, XNOR, NOT`
  - **关系运算符**：为`bit, bit_vector, integer*`类型定义
    - `=, /=, <, <=, >, >=`
    - `*`可为`std_logic, std_logic_vector`重载
  - 一元算术运算符`-`，为`integer`类型定义
  - 算数运算符`+, -, *`：为`integer*`类型定义
  - 连接运算符`&`：为字符串定义
