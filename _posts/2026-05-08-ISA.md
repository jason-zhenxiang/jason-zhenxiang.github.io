#### 指令与指令序列
- **指令的四大核心类型**
  - 1. **数据传输类：**在内存和处理器寄存器之间完成数据搬移
  - 2. **算术逻辑运算类：**对数据执行加减乘除、与或非等运算
  - 3. **程序序列与控制类：**改变程序的执行顺序，实现分支、循环、子程序调用等逻辑
  - 4. **I/O传输类：**在处理器和I/O设备之间传输数据，实现与外设的交互
- **寄存器传输表示法 Register Transfer Notation**
  - RTN是用来**描述硬件层面数据传输与操作的标准化符号体系**，是理解指令硬件行为的核心工具
  - **命名规则：**处理器寄存器用`R0、R5`表示；I/O寄存器用`DATAIN、OUTSTATUS`表示；内存位置用`LOC、A、VAR2`等符号表示
  - **内容表示：**用方括号`[ ]`表示一个位置中存储的内容，例如`[LOC]`代表内存LOC位置中存放的值
  - **传输表示：**用左箭头`$\leftarrow$`表示数据向目标位置的传输，箭头左侧永远是**目标存储位置**，右侧永远是**要传输的值**
- **汇编语言表示法**
  - 用助记符表示指令的操作（操作码），课件中用`Load、Store`等英文单词方便理解，商用处理器会使用缩写助记符（`LD、ST`），不同处理器的助记符存在差异，但核心逻辑一致
  - 用操作数对应RTN中的存储位置，明确指令的输入与输出
- **RISC与CISC指令集**
  - **精简指令集计算机 RISC**
    - 单字长指令，所有指令占用一个机器字（长度统一）
    - 算术运算的操作数必须放在寄存器中
    - 指令集规模小，典型为32条（体现Reduced属性）
    - 每条指令都在单时钟周期内完成，可高效利用流水线技术
  - **复杂指令集计算机 CISC**
    - 多字长指令，一条指令可以包含多个字
    - 允许操作数直接来自内存
    - 指令集规模大，多的可达数百条，指令功能齐全
    - 一条指令需要多个时钟周期执行（由于指令长）
- **RISC指令集特征**
  - 每条指令固定占用一个机器字（定长指令）
  - 采用**加载/存储（Load/Store）**架构
    - 只用Load和Store指令能够访问内存操作数
    - 算数/逻辑运算指令的操作数必须全部位于寄存器中，或是一个是指令内的立即数
- **指令执行与直线序列执行**
  - 程序和指令最初都存储在内存中，处理器执行程序的核心依赖一个特殊寄存器：**程序计数器（Program Counter, PC）**，PC中永远存放着**下一条要执行的指令的内存地址**
  - **直线序列执行：**PC自动递增、指令按内存顺序逐条执行
- **分支 Branching**
  - 程序仅靠顺序执行无法实现循环、选择逻辑，分支指令的核心作用，就是**给PC加载新的地址，打破PC的自动递增规则，改变程序的执行流**，其中新的目标地址称为**分支目标地址**
  - 条件分支是实现循环、选择的核心：先比较两个寄存器的内容，根据比较结果决定是否修改PC的值，跳转到目的地址
#### 指令格式
- **基础定义**
  - **机器指令：**指定处理器电路必须执行的操作指令，最终以二进制编码表示，通常用汇编代码对应
  - **指令集：**处理器能够执行的所有机器指令的集合，是ISA的核心主题
- **机器指令的要素**
  - 1. **操作码（Opcode）：**以二进制编码指定要执行的操作
  - 2. **源操作数引用：**指定指令执行所需的源操作数的位置
  - 3. **结果操作数引用：**指定指令执行结果的存储位置
  - 4. **下一条指令的地址：**通常由PC自动提供，分支指令会显示修改
- **指令的二进制表示**
  - **指令** = **操作码字段**（指定操作的二进制编码） + **地址字段**（指定操作数的地址信息）
- **指令地址字段格式分类**
  - 根据地址字段的数量，指令可以分为如下几种格式
  - **零定制指令：**仅Opcode，无地址字段
    - 操作逻辑为操作数位置隐含，如堆栈栈顶，适用于堆栈操作、停机/空操作指令
  - **一地址指令**：Opcode + 一个地址字段A
    - 操作逻辑为`[AC] OP A $\leftarrow$ AC`，AC为累加器，第二个操作数隐含在累加器中，适用于早期累加器架构处理器，单操作数运算
  - **二地址指令：**Opcode + 地址A1 + 地址A2
    - 操作逻辑为`[A1] op [A2]`，A1为目的地址，A2为源地址
  - **三地址指令：**Opcode + 地址A1 + 地址A2 + 地址A3
    - 操作逻辑为`[A2] OP [A3] $\leftarrow$ A1`，A1为目的地址，A2、A3为源地址
- **指令长度**
  - **定长指令：**所有指令长度完全相同，童话参观等于一个机器字长。是RICS的核心特征。
    - 优点为取指、译码逻辑简单，执行效率高，适配流水线；缺点为编码空间利用率低
  - **边长指令：**指令长度可以不同，从1字节到多字节不等，是CISC架构的特征
    - 优点为编码空间利用率高，可实现复杂操作；缺点是取指需要多次访存，译码逻辑复杂
  - 例子：操作码短的先设计
#### 寻址方式
- **立即寻址 Immediate mode**
  - 操作数直接卸载指令中，例如`Add R4, R6, $#200$`，#200为立即数
  - **适用场景：**定义常量、设置变量初值
  - **优点：**速度最快，无需额外访存；**缺点：**仅能提供常量，数值大小受地址字段位数限制
- **绝对寻址（直接寻址）**
  - 操作数放在内存中，内存的有效地址直接写在指令里，例如`Load R2, NUM1`，NUM1为内存符号地址
  - 适用场景：访问编译时地址已知的全局变量
  - 优点：仅需一次访问，地址计算逻辑简单；缺点：地址空间首先，只能访问固定内存位置
- **间接寻址**
  - 操作数的有效地址放在寄存器中，指令指定寄存器，CPU先从寄存器获取EA，再访存取操作数。地址为操作数的内容
  - **适用场景：**该方式支在CISC中使用，访问数组、列表等连续存储的数据结构
  - **优点：**完整地址不存放在指令中，修改寄存器的值就可以访问不同内存，灵活性高；**缺点：**需要访问两次内存
- **寄存器寻址**
  - 操作数直接存放在处理器寄存器中，指令只需要指定寄存器编号
  - **适用场景：**访问程序中高频使用的变量
  - **优点：**地址字段短，无需访存，执行速度快；**缺点：**寄存器数量有限，地址空间极小
- **寄存器间接寻址**
  - 操作数的有效地址存放在寄存器中，指令指定寄存器，CPU先从寄存器获取EA，再访存取操作数
- **变址寻址**
  - 有效地址 = 变址寄存器$R_i$的值 + 指令中给出的常量偏移X，计算EA时$R_i$的值不会被修改
  - **适用场景：**访问结构体成员、数组随机访问
  - **优点：**灵活性极高，适配高级语言数据结构访问
- 基址 + 变址寻址
- 相对寻址
  - 以程序计数器PC作为变址寄存器的特殊变址寻址，核心公式：`EA + [PC] + X`，X为带符号常量偏移
  - 适用场景：分支指令中指定目标地址；访问与当前指令位置相关的操作数
  - 优点：实现地址无关代码，程序在内存中的位置发生变化时，偏移量不变，无需重新编译
#### 子程序 Subroutimes
- 子程序的作用
  - 在程序中，同一个任务可能需要用不同数据多次执行，若每次都重复编写代码，会严重浪费内存空间，且维护难度极高
  - 我们将实现该任务的独立指令块称为子程序，在需要执行任务的位置，通过子程序调用指令跳转到子程序执行；子程序执行完毕后，通过返回指令跳回原程序继续执行
- 子程序链接
  - 子程序执行完毕后准确跳回正确的位置的方法
  - CPU执行Call指令时，PC已自动更新，指向Call指令的下一条指令地址，就是**返回地址**；将返回地址保存到链接寄存器中，供后续Return指令使用
